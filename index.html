从任务意图，到持续行动

RoBIOS 接收人类指令并连接物理执行：内核与插件共同管理行动状态和反馈，让系统能够随环境变化持续调整行动。

1. 为什么需要 RoBIOS？

在“数字 Agent + 物理工具”的模式中，Robot-Use Agent 负责规划和下发任务，物理工具被动执行。真实世界存在反馈延迟，且动作不可逆，因此这种模式面临两个显著问题。

对比维度Robot-Use AgentRoBIOS
01安全兜底数字 Agent 脱离物理现场；指令不合理或现场突变时，被动工具缺少本地裁决权，难以及时兜底。物理内核在现场负责准入检查、执行监测与异常处置。
02实时闭环高频状态变化若都回传大模型，会增加推理成本与响应延迟，限制实时反馈。内核在本地完成高频闭环，仅在需要上层重规划时向数字 Agent 汇总状态。

RoBIOS 的关键区别：执行裁决权交由物理内核，数字 Agent 保留规划职责。

设计原则

控制粒度适应可用预算
依据可用预算调节闭环粒度，平衡执行效果、反馈频率与推理开销。
能力通过插件持续扩展
围绕稳定内核，按需组合和复用具身能力。

2. 整体框架

规划层提出任务，物理内核管理执行。插件提供行动能力、人机交互、记忆，以及真实机器人与仿真环境的适配。

3. 物理内核

执行裁决
根据准入结果、资源占用和安全状态，决定动作的放行、阻断与停止。
状态管理
统一维护任务进度、执行记录、观测证据和验收结果。
闭环调度
协调各环节，根据反馈推进任务或请求重新规划。
异常处理
管理超时、失败、暂停、恢复和取消，跟踪停止确认与任务收尾。
